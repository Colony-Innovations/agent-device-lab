# Interaction fixture

An independent, dependency-free app for exercising the browser interactions an agent lab must drive. Run it with `npm run dev` (or `PORT=5351 node server.mjs`); `HOST` defaults to `127.0.0.1`, `PORT` to `5351`, and `/health` returns 200 `ok`. It has no state and no seeded layout defects: every page fits a 390 px viewport with no horizontal overflow, and the only horizontally overflowing content is the intentional carousel on `/scroll`, which scrolls inside its own region. Every page has an `h1`, a link "Home" (to `/`) and a `role="status"` element `#status` (`aria-live="polite"`), which is empty on load. Each interaction below writes the exact quoted text into `#status`. `uploads/notes.txt` is 79 bytes and `uploads/photo.png` (1x1 PNG) is 70 bytes.

**`/`** (h1 "Interactions"): links "Form controls" (`/form`), "Scroll and swipe" (`/scroll`), "Pointer" (`/pointer`), "Tabs" (`/tabs`), "Upload" (`/upload`), "Keyboard" (`/keys`). The pages are separate documents, so browser Back and Forward move between them.

**`/form`** (h1 "Form controls"): combobox "Plan" (options Free `free` selected, Pro `pro`, Team `team`); choosing one → `Plan: <option label>`, e.g. `Plan: Pro`. Checkbox "Email me updates" → `Email updates on` / `Email updates off`. Radio group "Size" with radios "Small", "Medium" (checked), "Large" → `Size: <label>`, e.g. `Size: Large`. Switch "Dark mode" (`div role="switch"`, `aria-checked="false"`, focusable), toggled by click or Space → `Dark mode on` / `Dark mode off`, with `aria-checked` updated to `true` / `false`. Checkbox "Locked option" is disabled. Button "Next step" → `history.pushState({step: 2}, '', '/form?step=2')`, shows heading (h2) "Step 2" and sets `Step 2`; Back (popstate) hides the heading and sets `Step 1`; Forward shows it again and sets `Step 2`. Loading `/form?step=2` directly shows the heading without changing the status.

**`/scroll`** (h1 "Scroll and swipe"; document at least 2500 px tall): region "Photos" (horizontal carousel, `overflow-x: auto`, `scroll-snap-type: x mandatory`, as wide as the content column) holding buttons "Photo 1" to "Photo 5", one per full-width slide; 150 ms after its scrolling stops → `Showing photo N` (N = round(scrollLeft / clientWidth) + 1). Group "Swipe card" (`#swipe-card`, `touch-action: none`) with a button "Card" inside; a touch swipe (touchstart/touchend, or pointerdown/pointerup with `pointerType` `touch`) whose horizontal travel exceeds 50 px and is at least its vertical travel → `Swiped left` / `Swiped right`; otherwise vertical travel over 50 px → `Swiped up` / `Swiped down`. The carousel and card are visible on load. List "Items" starts with buttons "Item 1" to "Item 10"; when the sentinel after the list scrolls into view, 200 ms later 10 more items are appended → `Loaded 20 items`, and on the next time the sentinel enters view → `Loaded 30 items` (30 is the maximum; the sentinel is below the fold on load, so nothing loads until the page is scrolled). Button "Back to top", below the fold at 844 px height, scrolls the window to the top → `Back at top`.

**`/pointer`** (h1 "Pointer"): button "Info"; mouse enter shows tooltip "More details" (`role="tooltip"`, the button's description) → `Tooltip shown`; mouse leave hides it → `Tooltip hidden`. List "Tasks" with draggable buttons "Task A", "Task B", "Task C" (HTML5 drag and drop); dropping one task on another moves the dragged task before the drop target → `Order: <letters in current order>`, e.g. dragging "Task B" onto "Task A" from the initial order → `Order: B, A, C`. Slider "Volume" (`div role="slider"`, 0 to 100, initial `aria-valuenow="50"`, 300 px wide track): pointerdown/move/up (with pointer capture) map the pointer's x across the track to 0 to 100, updating `aria-valuenow` as it moves; on pointerup → `Volume N`, e.g. releasing three quarters of the way along → `Volume 75`.

**`/tabs`** (h1 "Tabs"): link "Open help" opens `/help` in a new tab (`target="_blank"`); `/help` has h1 "Help" and button "Done" → `Done` (in the help tab's own status). Button "Open popup" → `window.open('/popup', 'popup')`; `/popup` has h1 "Popup", button "Send hello" (posts `hello` to its opener, same origin only, and sets its own status `Sent`) and button "Close window" (`window.close()`). When the message arrives, `/tabs` sets `Popup said hello`.

**`/upload`** (h1 "Upload"): file input "Attachments" (`multiple`) → `Attached: <name> (<size> bytes)` for each file, comma-separated in selection order, e.g. `Attached: notes.txt (79 bytes)` or `Attached: photo.png (70 bytes), notes.txt (79 bytes)`; an empty selection gives `Attached: none`. Button "Choose photo" calls `.click()` on a visually hidden (clipped 1 px, not `display: none`) file input "Photo" (`accept="image/*"`, `tabindex="-1"`), which opens the file chooser → `Photo: photo.png (70 bytes)`.

**`/keys`** (h1 "Keyboard"): search form with searchbox "Search"; Enter submits without navigating → `Searched for: <value>`, e.g. `Searched for: lamps`. Password field "PIN"; Enter → `PIN entered (N digits)`, where N is the value's length (the value is never echoed). Pressing `?` while focus is not in an input, textarea, select or editable element opens the modal dialog "Shortcuts" (named by its h2) → `Shortcuts opened`; Escape (native) or its button "Close" closes it → `Shortcuts closed`. `?` typed inside a field does not open the dialog.
